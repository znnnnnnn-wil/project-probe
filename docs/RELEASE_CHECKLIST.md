# 本轮改进发布与恢复

本轮 PR 合并仅更新 GitHub 源码。线上部署、定时备份安装、运营账户及成本单价配置需要单独执行，不因合并自动生效。

## 升级顺序

1. 从 main 的固定提交构建后端与前端，记录提交 SHA 和资源摘要；不要从含未提交改动的目录发布。
2. 核实无模型、语音、导入或支付操作正在执行，备份数据库与应用；在隔离库验证备份能还原。
3. 停止旧后端，再启动新 JAR，由 Flyway 依次执行 V10–V15。避免旧程序继续按旧租约规则写入。
4. 原子替换前端入口，保留旧哈希资源以支持已有浏览器。验证新端点、语音资源、桌面与手机路径。
5. 完成草稿跨设备恢复、纠错不扣次、一题体验无订单、笔记入材料与多次复测验收。
6. 支付保持 sandbox；正式收款接入仍暂停。任何沙箱或模拟记录不能作为真实收入。

回滚时应评估新数据兼容性，新表不应直接删除；数据库还原应先在隔离库校验，再选择维护窗口。不能直接覆盖用户最新订单和回答。

## 备份

`deploy/backup-database.py` 与同目录 service/timer 是待部署模板。适用固定目录 `/opt/project-probe-staging`、数据库 `projectprobe_staging`。安装脚本到该目录、服务到 systemd 后才可启用 timer；仓库合并不会自动安装。

脚本采用临时文件、目录700/文件600权限、成功校验后原子替换，默认保留14天且至少保留一份。只清理严格匹配文件名的普通备份文件，不跟随符号链接。`pg_restore --list` 只验证目录可读，不代表完整还原成功；完整恢复由隔离部署验收覆盖。

备份包含私人材料，应限制访问；恢复旧备份前需重新执行其后已受理的数据删除，不能让已删除材料重新出现。历史手工备份不在此定时清理范围，需运营者单独核对。

## 统计与运营

`OPERATOR_USER_IDS` 只填写已核实的运营账户UUID，默认空、无全站权限。`/api/operator/metrics` 和 `/api/operator/feedback` 受此限制。反馈回复是站内记录，不发送邮件或外部消息。

文本模型单价用 `MODEL_INPUT_PRICE_PER_MILLION`、`MODEL_OUTPUT_PRICE_PER_MILLION` 设置，单位人民币/百万token；默认-1表示未知。估算不含ASR、失败请求、重试和服务器成本，不能作为账单、毛利或净收入证明。

## 质量

模型评测仅使用合成案例，不替代真实用户反馈、人工技术复核或统计稳定性评估。上线模型与本地评测模型不一致时必须分别记录，不能迁移质量结论。
