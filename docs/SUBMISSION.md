# 参赛作品介绍（草稿）

**作品名称：** 项目追问官  
**拟选赛道：** Vibe Pay  
**一句话介绍：** 帮助 Java 后端实习求职者，围绕自己真实做过的项目练习连续技术追问，在有依据的复盘之后补充理解，再换场景复测。

## 解决的问题

准备面试的学生往往能写出项目经历，却难以解释某个功能是如何实现、为什么这样设计，以及并发和故障发生时会怎样。项目追问官围绕候选人自己的材料与回答开展练习，把“还没讲清楚”的地方转成可执行的补充任务。

## 产品闭环

用户创建项目档案，明确个人职责并核对事实。训练先让用户介绍项目，再逐题追问。复盘保留原回答、材料依据和下一步任务；用户补充实现说明与验证方式后，进入同一训练包的专项复测，查看前后回答。

事实区分材料提供、面试补充、AI 推断和待确认信息。材料不足不能证明用户没有做过项目。产品不编造性能提升和经历，不以一个不透明总分作为主要反馈，也不承诺 offer。

## 收费与交付

拟采用一次完整深挖加一次专项复测的次数包。当前 9.90 元为演示定价，未确定正式售价。服务端处理订单金额、支付确认、权益发放和训练扣次。重复支付通知不重复发放，训练中断可恢复，系统生成失败可返还权益。

**当前展示边界：** 无密钥默认规则演示，支付为开发模拟；用户确认用完即停后，百炼 qwen3.8-max-0902 已通过合成项目的真实事实提取、连续追问、复盘与专项复测，失败训练可恢复。本地私有配置使用 live，可在演示时展示真实模型状态；新增三类合成项目评测，异常一例需恢复，语义仅部分达标，近义重复与单题负担仍需改进。支付宝官方沙箱尚未联调，没有生产收款、真实收入、真实用户数或获奖记录。正式提交时应按届时实际验证结果更新，不将未完成能力写成已完成。

## 三分钟演示脚本

**0:00–0:25｜问题与定位**  
展示首页：“项目追问官面向准备 Java 后端实习面试的同学。它帮助你把自己的项目讲清楚。我们使用合成的校园预约项目，演示完整流程。先展示界面当前模型状态：真实模型版本已通过合成闭环；无密钥时为规则演示。支付始终标明开发模拟，不代表真实交易。”

**0:25–0:55｜材料与事实**  
打开合成档案，展示职责：“我只负责预约接口与数据库约束。”点击提取事实，展示材料提供与待确认标签。说明推断不会自动变成项目事实，用户可以修改并确认。保存核对结果。

**0:55–1:15｜模拟购买与交付**  
打开训练包页面，创建模拟订单并确认模拟支付，展示一份深挖、一份关联复测权益。说明价格由服务端控制；此处不会连接真实支付。返回项目开始训练。

**1:15–1:55｜连续追问与恢复**  
输入：“我在保存前检查座位是否空闲，再创建预约。”提交后，展示围绕这段回答的实现追问，继续补充事务与唯一约束。刷新页面，展示回答仍在。演示前可预备一轮已完成的合成训练，节省输入时间。

**1:55–2:25｜有依据的复盘**  
打开已完成报告，展示原回答和材料依据，阅读具体补充任务，例如取消状态如何与唯一约束配合。说明真实模型报告仍受结构与证据校验约束，技术建议需用户核对；规则演示不评判技术正确性。

**2:25–2:50｜补充与复测**  
围绕报告中的实际薄弱点补充材料，例如明确本人职责或补充验证步骤，保存并重新核对。进入关联复测，展示与该薄弱点相关的变化条件。打开预备的复测报告，展示两轮原回答及材料修订前后，不把回答变长当成能力提升。

**2:50–3:00｜现状与下一步**  
“产品闭环已经可以本地体验，百炼真实模型已通过合成流程；支付宝官方沙箱和生产资格仍需配置与验证。下一步以多项目输出质量和可靠支付交付为重点，不编造商业数据。”
