# PAYATHON 2026 产品审查与改造

## 定位

项目追问官：面向 Java 后端求职者的项目面试训练工具。价值不是生成通用八股答案，而是围绕用户亲自实现的项目连续追问，保留原回答证据，转成补充任务，并通过条件变化的关联复测检查解释是否完整。

官方赛事：<https://aipay.alipay.com/community/events/payathon-2026#tracks>。2026-10-13 核对：Vibe Pay 主赛道，报名截止 12 月 1 日，作品提交截止 12 月 9 日。关注产品完整度、支付集成度、商业化表现及用户反馈。并非 9 月已结束的激励活动。

## 原有问题

| 优先级 | 问题 | 改造验收 |
|---|---|---|
| P0 | 点击开始缺乏就近反馈，权益耗尽后表现像无响应 | 加载态、错误就近可见、提前显示剩余权益与补充入口 |
| P0 | 购买、付款、练习分离，付款后不知道从哪里继续 | 保留项目来源；付款确认后直接返回原项目，不根据回跳参数发权益 |
| P1 | 登录后仍是宣传首页，没有任务视图 | 工作台显示项目、待继续训练、报告、权益和下一步 |
| P1 | 长材料表单和所有事实堆叠 | 材料分组、专注核对视图、固定尺寸步骤导航、草稿与未保存提醒 |
| P1 | 报告只可阅读，补充任务无状态 | 服务端保存任务进度与笔记，版本冲突、越权、输入长度验证；不改原报告证据 |
| P1 | 原始订单编号突出，环境和交付说明不清楚 | 商品内容、价格、资金环境、交付与可恢复状态清楚呈现 |
| P2 | 缺少完整的评审材料和运行边界 | 当前模型/支付事实、验收证据、演示脚本和正式上线待办一致 |

## 保留的安全边界

- 使用已配置的真实模型，不以规则模式冒充 AI；免费额度用完停止，不自动切换付费模型。
- 当前线上是支付宝官方沙箱，不涉及真实资金，不代表正式商户收款已开通。
- 发放权益依赖服务端验签通知或可信交易查询；金额、应用、商户、环境和订单状态须一致。
- 同一训练继续不重复扣次；生成失败可恢复或返还训练次数，这不是资金退款。
- 不捏造技术分数、录用概率或项目事实，补充任务勾选只表示用户的自报进度，不表示系统独立验证。
- 不读取无关用户材料，不修改历史订单金额、不补发测试权益到真实用户账户。

## 本轮落地与验证

上述产品改造已于 2026-10-13 发布至 <https://39.96.27.134>。后端 151 项测试、浏览器 21 项回归通过，公网桌面及手机各 7 个视图的只读视觉检查通过；详细范围见 VERIFICATION.md 与 SERVER_DEPLOYMENT.md。原始真实模型的合成完整训练/复测验收与本轮视觉检查分开记录，不将夹具截图当成新模型或真实收款验收。

## 正式参赛前仍需完成

产品开通及正式应用配置、公网正式支付通知和补偿查询验证、有效真实付费用户、用户反馈与赛事报名/投稿必须由真实流程产生。自动测试、沙箱订单或合成账号不能作为商业化数据。
