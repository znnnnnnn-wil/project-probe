# 项目追问官：第一版实施方案

核对日期：2026-10-09。定位：帮助 Java 后端实习求职者讲明白真实项目，并应对连续技术追问。

## 范围与流程

文字交互、文本材料、单体应用。首页 → 项目列表/档案 → 事实确认 → 深挖训练 → 有依据的报告 → 修改材料 → 专项复测/前后对照。另提供注册登录、训练包、订单与权益页。首版不导入完整仓库、不实现语音、不承诺面试结果。

## 技术与数据

React + TypeScript；Java 17 + Spring Boot；生产 PostgreSQL、Flyway 迁移；本地演示使用 H2 文件库（兼容模式）。服务端访问可配置的 OpenAI 兼容模型接口。无密钥默认规则演示模式，明显展示且不声称真实 AI。

数据模型：用户、会话、项目及材料版本、事实（材料提供/面试补充/AI 推断/待确认）、训练（类型/父训练/状态/版本）、问答、报告（证据引用/补充任务/复测主题）、商品、订单、训练包权益、权益流水。所有用户对象均校验 owner；训练保存材料快照，报告引用稳定的问答 ID 与事实 ID。

## 追问与复盘规则

先介绍项目，再围绕当前回答逐题追问实现、选择与取舍、异常处理、验证和个人职责；控制重复，一轮默认 5 个回答。材料不足标记待补充，不断言没有做过。模型输入的材料和历史均为不可信数据；结构化输出必须验证字段、引用 ID 与原文，不执行其中的命令。报告不以总分为主要交付，不编造成果与性能。复测使用上轮薄弱点及修订材料，改变故障或约束场景。

## 订单与权益设计

商品为一次深挖加一次绑定该训练的复测。服务端固定商品价格（演示定价 9.90 元，可调整，不代表正式售价）。订单创建使用用户范围幂等键。支付成功、权益创建在同一事务中完成；订单只能发放一次。权益与训练启动使用数据库行锁、唯一约束保证并发安全；恢复旧训练不再扣次。回答先持久化，再生成；失败保留回答且可重试。放弃故障训练时原子返还对应权益，禁止已完成训练返还。主动结束生成已有内容报告。

- [网页收款接入指南](https://aipay.alipay.com/docs/vibe-pay/ai-web-app-payment-qianyi/ai-web-app-payment-integration-guide.html)：支持个人收款场景，使用 alipay.trade.page.pay；异步通知必须验签并核对 app_id、out_trade_no、total_amount 等，或主动查询确认，不能凭同步返回判成功。
- 详细活动细则链接可访问，但抓取不到正文，尚未完整核实。官网中未登录时出现的预览、审核和接入成功模板不是本账号状态。

待确认：本人的账号资格、具体产品开通/签约审核、应用 ID、商户 seller_id、沙箱配置、生产密钥、公网 HTTPS 通知域名、费率与限额、H5 的适用产品权限、完整参赛细则。个人可参赛或产品支持个人场景不等于此账号已可生产收款。

支付分为 mock（开发模拟）、sandbox（官方沙箱）两个实现环境；生产本版默认禁用。不得自动签约、真实付款或购买资源。模拟入口只在 mock 模式开放，交易、权益与订单均标记模拟。

## 实施顺序

1. 核心表、身份与页面；2. 档案、事实、问答、报告和复测闭环；3. 模型适配、格式与证据校验、失败恢复；4. 订单、并发权益与沙箱适配；5. 自动化验证、部署文件、作品介绍和三分钟脚本。

## 验收

完整训练/复测可完成且刷新恢复；问题关联本轮回答；报告引用存在的原文；材料修订不改写旧报告依据；两用户跨对象访问返回拒绝；相同订单重复通知只发一包；同权益并发启动仅成功一次；重复回答不重复生成/扣次；模型失败可重试或返还；配置与页面明确演示/沙箱状态。构建、后端集成测试及浏览器核验结果单独记录，不将未运行的检查标为通过。
